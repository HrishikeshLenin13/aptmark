# Editorial method review: design and React check

## Intent

Make the authored English methods inspectable and the complete family catalog reachable. The page is a reading-and-decision workspace, not a launch dashboard. No content approval or publication is generated by these tools.

## Existing tokens retained

Paper `#f8faf9`, surface `#fff`, ink `#25372e`, muted `#617166`, rule `#e2e8e4`, accent `#285e45`. System sans-serif remains the control/method typeface; the existing passage serif is unchanged. No new font, gradient, animation or icon library was added.

The composition stays left-aligned: scope controls, compact actual-count definitions, then the existing queue beside the item. One green-edged method section is the reading anchor; it groups a blueprint, method, rule, structure, steps and misconception checks. Line length is bounded at 76ch. Mobile controls stack and the count definitions use two columns. CSS is scoped to editorial classes.

## React / implementation review

- Server authentication precedes catalog filtering/facets. Client imports from the catalog module are type-only; candidate data is not bundled.
- The method view is a stateless, separately declared component. Props carry only the current authorized item; legacy items have an explicit fallback.
- Request sequence state lives in a ref and changes only in event handlers. Visual state remains React state. Stale responses and results arriving after Lock are ignored.
- Filter changes reset the family and item-specific notes. Query controls do not require an effect or mirrored derived-state loop.
- Review mutation controls keep the current item stable while saving. Lock invalidates result callbacks; it does not claim to undo an already sent server operation.
- Lists use question IDs, family IDs and fixed-source entries as keys. No third-party fetch client or new dependency was introduced.
- Native labeled selects and details, existing buttons, an accessible method region, table captions/headers and selected-button state support keyboard and screen-reader use.
- Existing approval/publication actions and server answer checking are preserved. Read-only metadata counts recorded states rather than claiming new human decisions.

Current React ref and Next.js global CSS documentation were consulted through Context7. Browser verification inspects mobile/tablet/desktop overflow, automated axe results, actual server responses and deliberate response reordering. These checks are not a complete accessibility certification.
